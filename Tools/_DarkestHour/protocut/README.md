# protocut — каскадное вырезание прототипов

Инструмент, которым вырезано ванильное оружие (PR «вырезание чужого оружия»). Работает по тексту YAML:
удаляет прототипы и ссылки на них, сохраняя форматирование, комментарии и якоря (`&name` переносится к
первой оставшейся ссылке `*name`).

- `dhidx.py` — индекс всех прототипов `Resources/Prototypes` (тип, id, файл, строки, родители) и всех скалярных ссылок.
- `cut.py del.json` — каскад: `{"seed": [["entity", "Id"], ["latheRecipe", "Id"], ["Tag", "Id"], ...]}`.
  Ссылка в списке → элемент удаляется; ключ словаря (инвентари, веса) → пара удаляется; одиночные поля
  (`latheRecipe.result`, `listing.productEntity`, `cargoProduct.product`, плата `prototype`, `stealGroup`,
  контейнер с одним `EntSelector`, `tableId`, `pack` автомата) → удаляется весь прототип, и каскад идёт дальше.
  Дети удалённого родителя удаляются. Что не разобрано правилами — печатается как `MANUAL`.
  Итог пишется в `del.out.json`.
- `empties.py out.json` — опустевшие коллекции в изменённых файлах (относительно `DH_BASE`, по умолчанию
  `origin/master`): заполнения ящиков/шкафов, таблицы, инвентари автоматов, наборы рецептов, спавнеры → прототип
  удаляется (список — в `out.json`, его надо снова прогнать через `cut.py`); остальное → удаляется пустой ключ.

Порядок: `cut.py` → `empties.py` → `cut.py` с удалёнными из empties → … пока не перестанет меняться.
Потом: ссылки в C# (строки и `[TestPrototypes]`), гайдбук (`GuideEntityEmbed`), `Resources/migration.yml`
(`Id: null` для всего, что стоит на картах; цели миграций, которые удалены, тоже `null`), осиротевшие теги и
абстрактные базы. Карты движок чистит сам: сущности с `null`-миграцией создаются и удаляются после загрузки.

Внимание: id, который есть у живого прототипа другого типа (рецепт `MMI` и сущность `MMI`), каскад не трогает —
иначе удалится лишнее.
